# Learning rate as a stated grid, queued onto cards as they free.
#
#   python scripts/gpu_queue.py --jobs scripts/jobs_lr_probe.txt
#
# Nothing is set on these lines but the loss and the rate, because
# scripts/lr_probe.sh now defaults to the eps ladder's recipe exactly -- 40000
# steps, cosine to a 0.02 floor from 60% of the run, norm=batch, tanh,
# adam_eps=1e-8, batch 64, clip 5000, warmup 2000, same datasets, same
# numerics, same seed. Learning rate is the only difference between a cell here
# and an arm there, which is the point: the results are quotable side by side.
#
# That is also why the naming of variables on every line, which earlier jobs
# files insisted on, is absent here. The reason for that insistence was that a
# default disagreed with the run being compared against; now they agree, so
# restating them would be six more places for the two to drift apart.
#
# THE 3e-4 COLUMN IS NOT HERE. At the ladder's own rate these cells reproduce
# ladder arms bit for bit, seed included, so they come from
# results/ddsp/eps_ladder_adam1e8 instead of costing ~16 GPU-hours to compute
# twice. Report them from there.
#
# 12 cells x ~5.5h at ~2 steps/s. Ordering is eps1 first, then the control,
# then the dead arm: a queue that only gets two thirds of the way still answers
# the live question.
#
# Known limitation, for the caption rather than for a reviewer to find: equal
# budget per cell means the low-rate cells are the least converged, so a poor
# result at 3e-5 conflates "wrong rate" with "not enough steps". Equal budget
# is still right; it just has to be declared. Report best-per-arm, not
# best-overall.

# --- eps1: the only log arm still descending, i.e. the one the objection is
#     actually about. Still above the constant-predictor floor (0.0789 vs
#     0.0473, ratio 1.67), so it has not beaten the mean -- but slow and stuck
#     are different claims and only one of them is a rate problem.
LOSSES="L1_STFT_eps1" LRS="3e-3" scripts/lr_probe.sh "{gpu}"
LOSSES="L1_STFT_eps1" LRS="1e-3" scripts/lr_probe.sh "{gpu}"
LOSSES="L1_STFT_eps1" LRS="1e-4" scripts/lr_probe.sh "{gpu}"
LOSSES="L1_STFT_eps1" LRS="3e-5" scripts/lr_probe.sh "{gpu}"

# --- the linear control, on the same axis. Without it, "linear is as
#     insensitive to rate as log is" is an assertion rather than a measurement.
LOSSES="L1_STFT" LRS="3e-3" scripts/lr_probe.sh "{gpu}"
LOSSES="L1_STFT" LRS="1e-3" scripts/lr_probe.sh "{gpu}"
LOSSES="L1_STFT" LRS="1e-4" scripts/lr_probe.sh "{gpu}"
LOSSES="L1_STFT" LRS="3e-5" scripts/lr_probe.sh "{gpu}"
