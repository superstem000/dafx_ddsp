# guitar_acoustic: linear wins it jointly, and its quiet region is large.
#
#   python scripts/gpu_queue.py --jobs scripts/jobs_diffsynth_gtacoustic.txt
#
# BUILD THE DATASET FIRST, under tmux -- 22 GB stream, no resume:
#
#   OUT=nsynth-gtacoustic CLASS=guitar_acoustic scripts/get_nsynth.sh
#
# ~966 files per 25000 sampled, so roughly 11,200 in the full train split,
# ~1.4 GB. It only has to exceed h2of_kb's 8064 for data.py:92.
#
# WHY THIS CLASS.
#
#   joint mfcc, this class      magx 7.6533   hyb 7.7443   log 7.7851
#
# magx beats BOTH compressed arms, one of only three classes that does -- the
# others being reed_acoustic and keyboard_acoustic. And it is the quietest of
# the three by every measure, which is the reason for picking it over them:
#
#   floor_dB                      -104.0     (empty quiet, not a noise floor)
#   bins% 80-100 / 100-120     35.9% / 18.3%
#   bins below -80 dB              55.1%
#   bins below -100 dB             19.2%
#   eng% 0-20 dB                   74.8%     (so 54% of the bins hold ~0.1%)
#   frames active                  38%       (plucked, long decay)
#
# 54% of its bins sit 80-120 dB down carrying about a tenth of a percent of the
# energy. That is the largest reweighting-per-unit-energy of the three linear
# classes, and reed's is the opposite kind: floor -90.7, a real noise bed.
#
# THE PRIOR, recorded so the run can contradict it. At epoch 199, before any
# real audio, guitar_acoustic is the second WORST class for magx:
#
#   pre_*, ep199                magx 10.6962  hyb 10.1194  log 9.5544
#
# magx trails log by 1.14 there and leads by 0.13 after the real phase, so this
# class swings further across that phase than any of the three. Whether the
# swing survives class-specific training is the question.
#
# Two other measurements on it, for whatever they turn out to be worth:
#   paired residual ratio, normalised, 40-60 / 60-80 / 80-100:  1.96 / 3.60 / 2.83
#   harmonic anchoring H/I, 0-2k / 2-4k / 4-7k:                 28.1 / 3.5 / 2.7
# Neither predicted the outcome across the nineteen classes (r = -0.10 and
# -0.26 respectively), so they are context, not evidence.
#
# SCHEDULE: THE STOCK ONE. 400 epochs, decay 0.99, lr 1e-3 -- no overrides, so
# the real phase runs epochs 200-400 at 101 steps/epoch, 20,200 steps, lr
# 1.340e-4 -> 1.813e-5. That is 0.40x the joint run's 50,000 steps, the same
# deficit keyboard's first attempt had, and it is deliberate here: this is the
# stock protocol, directly comparable to the keyboard attempt-1 numbers already
# on record.
#
# ID_DIR is h2of_kb: data.py:92 draws len(id_dat) indices from the ood set, so
# its 8064 files fix the training set at 6451 clips -- the same count every
# class run so far has used, which is what makes them comparable to each other.
#
# Runtime ~2h50m for the 200 real-phase epochs, as keyboard's took.

ID_DIR=external/diffsynth/data/h2of_kb OOD_DIR=external/diffsynth/data/nsynth-gtacoustic RESUME=pre_magx_halfw scripts/ds_run.sh real_gt_magx_halfw resume_real "{gpu}" trainer.checkpoint_every_n_epochs=50 model.log_grad=false model.sw_loss.log_mag_w=0 model.sw_loss.power=1 schedule.sw_w.end_v=0.5
ID_DIR=external/diffsynth/data/h2of_kb OOD_DIR=external/diffsynth/data/nsynth-gtacoustic RESUME=pre_hybridx    scripts/ds_run.sh real_gt_hybridx    resume_real "{gpu}" trainer.checkpoint_every_n_epochs=50 model.log_grad=false model.sw_loss.power=1 model.sw_loss.log_eps_v=1e-2
ID_DIR=external/diffsynth/data/h2of_kb OOD_DIR=external/diffsynth/data/nsynth-gtacoustic RESUME=pre_logx_halfw scripts/ds_run.sh real_gt_logx_halfw resume_real "{gpu}" trainer.checkpoint_every_n_epochs=50 model.log_grad=false model.sw_loss.power=1 model.sw_loss.log_eps_v=1e-2 model.sw_loss.mag_w=0 schedule.sw_w.end_v=0.5
