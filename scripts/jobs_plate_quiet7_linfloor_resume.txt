# Finish lin_db40 and lin_db80 after the disk filled underneath them.
#
#   python scripts/gpu_queue.py --jobs scripts/jobs_plate_quiet7_linfloor_resume.txt
#
# WHAT HAPPENED. The filesystem hit 100% while these two were training. The
# checkpoints survived intact -- encoder_last.pt is byte-identical in size to
# every other arm's -- but history.json was truncated mid-record at a 228 KiB
# block boundary and the per-arm .log was cut mid-line. monitor_sweep drops an
# arm whose history.json will not parse, silently, which is why the two columns
# vanished from the table rather than showing an error.
#
# The files were repaired by decoding records until the truncation and
# rewriting: 318 rows to step 36800 for db40, 312 to 36200 for db80. The raw
# truncated bytes are kept beside them as history.json.trunc.
#
# THE REPAIR HAD TO COME FIRST. train_encoder reads history.json on resume
# inside a bare `except Exception: pass` (train_encoder.py:1021), so resuming
# against the corrupt file would have caught the JSONDecodeError, started the
# history empty, and thrown away every row before 36800 -- quietly, with the
# run looking healthy.
#
# FORCE=1 because eps_ladder refuses a directory that already holds results,
# which is exactly what these are. Resuming from each arm's OWN encoder_last.pt,
# not from quiet7_pre.
