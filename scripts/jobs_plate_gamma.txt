# The diffsynth gamma ladder, on the plate. Same exponents, same pretraining.
#
#   python scripts/gpu_queue.py --jobs scripts/jobs_plate_gamma.txt
#
# WHY. The diffsynth arms are a ladder in one variable -- the exponent gamma on
# INTENSITY -- with mag at 1.0, magx at 0.5, gam03 at 0.3 and log at the limit.
# On real held-out audio the ordering reverses along it: magnitude-linear wins
# every compressed rung and loses every log-domain one, with the crossover
# between g0.15 and g0, and Stevens' 0.3 sitting well inside the region where it
# wins. That is one synthesizer, one dataset, one architecture. The plate is a
# second system with TRUE parameters, so it can say whether the ordering is a
# property of compression or a property of harmor.
#
# THE PLATE HAS NEVER HAD THE g=1 RUNG. _stft_mag returns .abs(), so every loss
# in losses.py is magnitude-domain: L1_STFT is I^0.5, the eps rungs are I -> 0,
# and there was no I^1.0 arm at all. That is exactly why the zero-gradient dead
# zone appeared on diffsynth and not here -- d|a^2 - t^2|/da = 2a vanishes at
# silence, d|a - t|/da = +-1 does not -- and why "linear" meant two different
# things across the two systems. L1_STFT_g1 supplies the missing rung, so the
# dead zone can be reproduced or ruled out on a task with ground-truth
# parameters rather than inferred from a frozen training curve.
#
# AND L1_STFT_pow WAS NOT STEVENS. It applies gamma to MAGNITUDE, so pow at 0.3
# is I^0.15 -- half the exponent it reads as. Loudness ~ I^0.3 needs
# magnitude^0.6. pow is left untouched because published runs use it; g03 is the
# arm that actually sits where hearing does. This is the same trap diffsynth's
# spectrogram_loss asserts against with its `power == 2` check.
#
# THE WIRING CHECK IS NOT A TRAINING ARM. g05 is I^0.5, and (m^2 + e^2)^0.5 = m
# for m >> e, so it IS L1_STFT except for a soft floor below magnitude 1e-7.
# Two functions that agree to six figures do not need 7 GPU-hours to prove it --
# run the numeric check instead, and do it before queueing anything:
#
#   python - <<'EOF'
#   import torch
#   from src.loss.losses import LOSS_COMPONENTS as L
#   x = torch.randn(2, 44100); y = x + 0.01*torch.randn_like(x)
#   for n in ("L1_STFT","L1_STFT_g05","L1_STFT_g03","L1_STFT_g1","L1_STFT_eps1e7"):
#       print(f"{n:<18}{float(L[n](x,y).mean()):.6f}")
#   EOF
#
# L1_STFT_g05 must land on L1_STFT. If it does not, the squaring or the eps
# placement in _compress_mag's "gpow" branch is wrong and every arm below is
# measuring something other than its exponent.
#
# EPS. 1e-7 on magnitude throughout, squared to 1e-14 on intensity inside gpow,
# which is the family default and matches the c1 rungs. So g03 against
# L1_STFT_eps1e7 differs in the exponent and in nothing else -- same knee, same
# signal level, the same one-variable discipline diffsynth's gam03 has against
# its log arm.
#
# NOT A PURE LADDER IN OPTIMISATION TERMS, and this should be said rather than
# discovered. The losses use x^gamma, not Box-Cox (x^gamma - 1)/gamma, so the
# gradient carries a factor of gamma: d/dx (x^2 + e)^g = 2g x (x^2 + e)^(g-1),
# which at unit amplitude is 2g. So g03 trains with roughly 0.6x g05's step on
# the spectral term, from the missing normalisation rather than from the
# compression under test. Adam absorbs most of a uniform factor once the
# spectral term is the whole objective; where it does not is the crossfade,
# while the parameter loss is still being traded against.
#
# PRETRAINING AND NORM. Masuda & Saito's schedule as fractions -- parameter loss
# alone for 12.5%, crossfade to 50%, param_w 10 -> 0. NORM=batch for the same
# reason jobs_ppre_hybrid.txt uses it on every line: GroupNorm normalises within
# one example and permits an encoder that maps every input to the same output,
# which is this encoder's documented failure mode, while BatchNorm makes that
# solution unreachable.
#
# ONE SHARED BASE, AND IT IS NOT MERELY AN EFFICIENCY WIN. diffsynth trains
# epochs 0-50 once as pre_base and resumes every variant from it. Doing the same
# here removes a confound rather than just 5000 x 6 duplicated steps.
#
# The confound: spec_w == 0 does drop the spectral term from the graph, so the
# objective during the hold is param_w*param_term + hinge for every arm. But it
# is then divided by loss_scale, which is fixed at step 1 from THAT ARM'S OWN
# spectral loss -- measured at 2.12 for L1_STFT and 4483 for L1_STFT_g1, a
# factor of 2000. So "the parameter-only phase is identical for every arm" is
# false as the ladder currently stands, in a way that is invisible in the logs
# because train_loss reports the undivided spectral value.
#
# Training the hold once and resuming fixes it exactly: --resume restores
# loss_scale from the checkpoint (deliberately -- recomputing it would rescale
# every gradient and silently change the effective learning rate mid-run), so
# every arm inherits ONE divisor and starts the crossfade from bit-identical
# weights and optimizer moments.
#
# --lr-decay-end 40000 on a --steps 5000 run is what makes the base's learning
# rate the first 5000 steps of the 40000-step schedule rather than a compressed
# 5000-step one: s0_end = stage0_end_step or lr_decay_end or steps.
# --param-hold-frac 1.0 holds param_w at 10 for the whole base, since the
# handover reads its boundaries as fractions of --steps.
#
# WHAT THIS DOES NOT FIX, and it should be stated. param_w = 10 is weighed
# against each arm's own spectral magnitude during the crossfade, and those span
# five decades here (g1 ~200, eps1e7 ~0.01). loss_scale cancels in that ratio,
# so it is param_w itself that means different things across arms. diffsynth has
# the same property but its losses sit within about one decade of each other.
# Left alone because changing it would depart from the published recipe; noted
# because a reviewer comparing the crossfade across arms is comparing this too.
#
# ORDERING. The base alone in stage 1, because every arm below depends on it and
# gpu_queue runs stages in order. Then the anchor, the two new exponents, the
# log and hybrid ends, and the raw arm last. Every number here is reported as a
# ratio against L1_STFT and the constant-predictor floor, so a queue that stops
# halfway is still interpretable -- provided the base and the anchor got in.

# STAGE the shared parameter-only base. ~1 hour. EVERYTHING BELOW RESUMES FROM
# IT, so if this fails the rest must not start -- which is why it is alone in
# its stage.
NORM=batch HEAD_BOUND=tanh ADAM_EPS=1e-8 HEAD_HINGE=0 STEPS=5000 OUT=results/ddsp/gamma_pre ARMS="L1_STFT" EXTRA="--param-loss l1 --param-w 10.0 --param-hold-frac 1.0 --lr-decay-end 40000" scripts/eps_ladder.sh "{gpu}"

# STAGE the anchor, first of the resumed arms
NORM=batch HEAD_BOUND=tanh ADAM_EPS=1e-8 HEAD_HINGE=0 STEPS=40000 OUT=results/ddsp/gamma_ppre ARMS="L1_STFT"     EXTRA="--resume results/ddsp/gamma_pre/L1_STFT/encoder_last.pt --param-loss l1 --param-w 10.0 --param-hold-frac 0.125 --param-ramp-frac 0.375" scripts/eps_ladder.sh "{gpu}"

# STAGE the two exponents the plate has never had
NORM=batch HEAD_BOUND=tanh ADAM_EPS=1e-8 HEAD_HINGE=0 STEPS=40000 OUT=results/ddsp/gamma_ppre ARMS="L1_STFT_g03" EXTRA="--resume results/ddsp/gamma_pre/L1_STFT/encoder_last.pt --param-loss l1 --param-w 10.0 --param-hold-frac 0.125 --param-ramp-frac 0.375" scripts/eps_ladder.sh "{gpu}"
NORM=batch HEAD_BOUND=tanh ADAM_EPS=1e-8 HEAD_HINGE=0 STEPS=40000 OUT=results/ddsp/gamma_ppre ARMS="L1_STFT_g1"  EXTRA="--resume results/ddsp/gamma_pre/L1_STFT/encoder_last.pt --param-loss l1 --param-w 10.0 --param-hold-frac 0.125 --param-ramp-frac 0.375" scripts/eps_ladder.sh "{gpu}"

# STAGE the log end and the hybrid, so the whole ladder sits in one directory
NORM=batch HEAD_BOUND=tanh ADAM_EPS=1e-8 HEAD_HINGE=0 STEPS=40000 OUT=results/ddsp/gamma_ppre ARMS="L1_STFT_eps1e7" EXTRA="--resume results/ddsp/gamma_pre/L1_STFT/encoder_last.pt --param-loss l1 --param-w 10.0 --param-hold-frac 0.125 --param-ramp-frac 0.375" scripts/eps_ladder.sh "{gpu}"
NORM=batch HEAD_BOUND=tanh ADAM_EPS=1e-8 HEAD_HINGE=0 STEPS=40000 OUT=results/ddsp/gamma_ppre ARMS="L1_STFT_hyb1e2" EXTRA="--resume results/ddsp/gamma_pre/L1_STFT/encoder_last.pt --param-loss l1 --param-w 10.0 --param-hold-frac 0.125 --param-ramp-frac 0.375" scripts/eps_ladder.sh "{gpu}"

# STAGE g1 WITHOUT pretraining -- the one raw arm worth its 7 hours.
#
# The dead zone is the mechanism the whole power-vs-magnitude section rests on,
# and right now it is a diffsynth-only observation inferred from a frozen
# training curve: spec_mag and spec_mag_halfw sat bit-identical for 16 epochs
# while spec_magx_halfw trained. The plate has ground-truth parameters, so it
# can say whether an I^1.0 loss freezes from random init on a task where
# "frozen" can be checked against the constant-predictor floor rather than
# against itself. If this freezes and the pretrained g1 above does not, the
# handover is what rescues it -- measured, not assumed.
#
# g03-raw is deliberately absent: eps_ladder_adam1e8 already covers that region
# spectral-only, and nothing about it is new.
NORM=batch HEAD_BOUND=tanh ADAM_EPS=1e-8 HEAD_HINGE=0 STEPS=40000 OUT=results/ddsp/gamma_raw ARMS="L1_STFT_g1"  scripts/eps_ladder.sh "{gpu}"
